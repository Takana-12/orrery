# Runbook：Orrery（旧称 Agent Control Room）v0.4

- 対象：Windows 11、個人のローカル利用
- 現状の到達点と未対応は [技術選定レポート §9](01-技術選定レポート.md) を参照

## 1. セットアップ

| 必要なもの | 確認方法 |
|---|---|
| Node.js 24以上 | `node --version` |
| Claude Codeにログイン済み | `claude auth status` で `loggedIn: true` |
| Codexにログイン済み | Codexアプリ、またはVS Code拡張、または `codex login` でChatGPTにログイン |
| Codexのバイナリ | 次の順で自動検出：環境変数 `CODEX_BIN` → PATH上の `codex.exe` → VS Code拡張（openai.chatgpt）の同梱バイナリ |

リポジトリのルートで依存を導入する。

```powershell
npm install
```

Control Roomは認証情報を読まない。ログインは各社のツール側で済ませておく。

## 2. アプリを作る・起動する・終了する

Control RoomはWindowsのアプリ（Electron）として動く。最初に一度だけアプリを作り、スタートメニューに登録する。

```powershell
npm run install-app
```

- `release\Orrery-win32-x64\Orrery.exe` が作られ（約740MB）、スタートメニューに「Orrery」が登録される。以後のコードの更新は、アプリの設定の「更新して再起動」で反映できる（下記）。
- デスクトップにもショートカットが欲しい場合は `powershell -ExecutionPolicy Bypass -File apps\desktop\install-shortcuts.ps1 -Desktop`、登録を消す場合は `-Remove`。
- 署名していないexeなので、環境によってはWindowsが警告を出す可能性がある（自分でビルドしたものなので通常は出ない）。

**起動：** スタートメニューから「Orrery」を開く。

**ウィンドウを閉じても終了しない。** 通知領域（タスクトレイ）に残り、エージェントは動き続ける。判断が必要になるとWindowsの通知が出て、トレイのアイコンが琥珀色になり、タスクバーが点滅する。通知かトレイのアイコンをクリックするとウィンドウが戻る。

**終了：** トレイのアイコンを右クリック →「終了（エージェントも停止）」。動いている作業があれば確認が出る。

**Windowsの起動時に開始：** トレイのメニューでチェックを入れる。その場合はウィンドウを出さずにトレイで待機する。

二重に起動しようとすると、既に開いているウィンドウが前面に出る。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `CONTROL_ROOM_PORT` | `4780` | アプリ内部で使うポート（`127.0.0.1` のみ） |
| `CONTROL_ROOM_HOME` | `%LOCALAPPDATA%\AgentControlRoom` | データの保存先 |
| `CODEX_BIN` | 自動検出 | `codex.exe` のパス |

開発時は、作り直さずに `npm run app` でアプリを起動できる。`npm start` は従来どおりブラウザ（Edge）で開く開発・テスト用の起動方法。

## 3. 使い方

画面は左右2つに分かれる。左が作業の一覧、右が「要対応」または選んだ作業の画面。

1. 左上の「新しい作業」で、プロジェクトと頼むことを入力して始める。名前は自動で付く（作業の画面の鉛筆アイコンで変えられる）。新しいフォルダは「フォルダを選ぶ」でエクスプローラーの標準のダイアログから選ぶ。
   - 「始める」を押すと、入力欄はすぐ空になり、左の一覧に「送信中」として出る。画面は新しい作業のまま残るので、続けて次の作業を頼める。送れなかったときは、書いた内容が入力欄に戻り、一覧に「送れませんでした」と出る。
   - 書きかけの内容は、ほかの画面を開いて戻っても残っている。
   - 入力欄の上に、各エージェントの利用枠の残り（5時間枠と週間枠）が小さく出る。ほかのアプリでの利用も含む。
   - **モデルと思考量：** 「Opus 5.5　思考量 中」のようなボタンを押すと、モデルが縦に並んだシートが開く。下のスライダーで思考量を選ぶ。最初は各エージェントの先頭のモデルと「中」になっていて、変えると次回から覚えている。
   - **承認：** 「毎回わたしが決める」「ファイル編集は自動で許可（Claude Codeのみ）」「エージェントの審査に任せる」から選ぶ。
2. エージェントが質問や承認を求めると、右の「要対応」に依頼が出る。なければ「いま判断が必要なものはありません」と表示される。
3. 依頼に答える。すべての作業の依頼が「要対応」に並び、作業を開かずにその場で答えられる。いちばん古い依頼が1つ開いた状態で表示され、ほかは1行に閉じている（行をクリックするか、`j`/`k` で選んで `Enter` で開く。いくつ同時に開いてもよい）。1つに答えると、次の依頼が自動で開く。答えた依頼はすぐに消える。エージェントの受領が8秒たっても確認できないときだけ、その旨を添えてもう一度出る。
   - エージェントが文章で尋ねてきた質問（「A案とB案のどちらにしますか」など）も、選択肢つきの依頼として出る。答えは次のメッセージとしてエージェントに送られる。
4. 返答が終わった作業は「まだ見ていない結果」に並び、左の一覧に青い点が付く。開くと消える。
5. 左の一覧で作業を選ぶと、その作業の画面が開く。会話を読み、下の欄から追加の指示を送り、「中断する」「メモリを空ける」「片付ける」を使う。
6. 「片付ける」は一覧から外すだけで、会話も履歴も消えない。左下の箱のアイコンから戻せる。

**完了の確認：** 新しい作業で「検証コマンド」（例: `npm test`）を入れておくと、エージェントの返答が終わるたびにControl Roomがそれを実行する。成功すれば「完了にできる作業」に、失敗すれば「検証に失敗した作業」に並ぶ。「完了にする」を押すと片付けられる。「失敗したら結果をエージェントに戻して直させる」を選ぶと、2回まで自動で差し戻す。

**あなたの作業：** エージェントの作業が終わり、人間にしかできないこと（PRのマージ、外部サービスの設定、目視確認など）が残ったときは、返答を読み取って手順のリストにし、「要対応」の中の「あなたの作業」に出す。全部にチェックを入れると、その作業は完了になる（片付けられる）。

**コマンドのリンク：** エージェントの文章の中のコマンド（例: `gh pr merge 707 --merge`）は、青い下線つきで表示される。クリックすると、実行する内容と場所の確認が出て、その作業のフォルダで実行される。結果はその場に表示され、会話にも記録される。「結果をエージェントに伝える」で返せる（失敗したときは、直してもらうためのボタンになる）。実行できるのは、その作業でエージェントが実際に書いたコマンドだけ。

**保存データの整理：** 設定の「保存データ」に、いまのサイズと件数が出る。片付けた作業の会話記録とアプリのキャッシュを、古さを選んで削除できる。作業の一覧・判断の履歴・検証結果は残る。

**見回らなくて済むための工夫：**

- 実行中の作業は、左の一覧に「いま何をしているか」（直近のコマンドやファイル）が1行で出る。3分以上動きがないと「n分動きなし」と琥珀色で出る。
- エージェントが動いている最中でも、次に頼むことを書いて「終わったら送る」を押しておける。いまの作業が終わった時点でOrreryが自動で送る（取り消しもできる）。中断や異常で止まった場合は送らずに残す。
- 作業の画面に「次の判断待ちへ」ボタンが出る。ほかの作業が判断を待っているときに、そこへ直接移動する。
- 「まだ見ていない結果」は「すべて見たことにする」でまとめて消せる。見終わった完了は、左の一覧の「見終わったn件を片付ける」でまとめて片付けられる。

**承認を任せる：** 「エージェントの審査に任せる」は、Claude Codeの auto モード、Codexの auto_review を使う。各エージェント自身の審査機能が許可・拒否を決め、審査が通さなかったものと質問だけが要対応に届く。Orreryが独自に判断しているわけではない。個別の承認カードで「この作業の間は常に許可」を選ぶと、同じ種類の操作はその作業の間は聞かれなくなる。

**利用状況：** 左下のメーターのアイコンから開く。サービスごとに、ログイン状態、利用枠の使用率とリセットまでの時間、今日と直近7日のトークン数が見える。トークン数はOrreryから動かした作業の分だけで、利用枠（残り何%か）はアカウント全体の値で、ほかのアプリでの利用も含む。Claude Codeの利用枠は、Claude Code自身の `/usage` と同じ情報をClaude Agent SDK経由で取得している（SDKでは実験的なAPIのため、将来使えなくなった場合は、Claude Codeが作業中に知らせてきた範囲だけの表示に戻る）。Codexは公式のapp-serverから取得している。

**ログアウトされたとき：** 起動時と5分ごとに各サービスのログイン状態を確認する。ログアウトされていると、左の一覧の上と新しい作業の画面に案内が出る。「ログインする」を押すと、そのサービスの公式のログインページが既定のブラウザで開く。ログインが終わると自動で反映される。パスワードをOrreryに入力することはない。

**作業ごとのフォルダ（git worktree）：** プロジェクトがgitのリポジトリなら、作業を始めるたびにOrreryがその作業専用のworktreeを `%LOCALAPPDATA%\AgentControlRoom\worktrees\` に作り、新しいブランチ `orrery/<日付>-<id>` で作業させる（元はプロジェクトのいまのHEAD）。プロジェクトのフォルダ自体は変更されないので、同じプロジェクトで何件並べても互いに干渉しない。作業の画面の上部にブランチ名が出る。gitでないフォルダでは、これまでどおりフォルダで直接作業する。

- **片付け：** 「完了にする」か「片付ける」と、worktreeは自動で削除される。未コミットの変更は先にそのブランチにコミットして残す（フックは動かない）。ブランチは、新しいコミットがない・プロジェクトのHEADに取り込み済みなら削除し、取り込まれていない変更があれば残す（会話に結果が記録される）。残ったブランチのマージはあなたが行う。
- **戻す・再開：** 片付けた作業を戻したり続きを指示したりすると、同じ場所にworktreeを作り直す（ブランチが残っていればその続きから）。
- **node_modules：** worktreeには、プロジェクトの `node_modules` をリンク（ジャンクション）で共有する。エージェントがパッケージを追加すると、プロジェクト側にも入る。**このworktreeを手で `git worktree remove --force` しないこと**（gitがリンクの先までたどり、プロジェクトの `node_modules` を消してしまう）。Orreryは削除の前にリンクを外し、リンクが残っていれば削除を中止する。
- 削除に失敗したとき（ファイルが開かれていた等）は、次の起動時にもう一度試す。

**アプリの更新：** ウィンドウを閉じても終了しないので、コードを変えたら設定の「アプリの更新」を使う。ソースに変更があると「ソースが更新されています」と出る。「更新して再起動」を押すと、アプリを使ったまま `release\.staging` に新しいバージョンを作り（20秒前後）、できあがると閉じて入れ替え、新しいバージョンで開き直す。入れ替えに失敗したときは前のバージョンで開き直し、`release\update.log` に記録する。「再起動だけする」は作り直さずに開き直す（記録は `%TEMP%\orrery-restart.log`）。動いている作業は止まり、起動後に「中断」として表示される。依存パッケージを変えたときは先に `npm install` を実行する。

- プロセスを手で終了したりポートを空けたりする必要はない。閉じきらないOrreryのプロセスは入れ替えの前に終了させる。起動時にポートを古いOrreryが使ったままなら、それを終了して起動し直す（Orrery以外のプログラムが使っている場合は、これまでどおりエラーを表示する）。終了処理は8秒で打ち切る。

**バックグラウンドの作業を待っているとき：** Claude Codeがバックグラウンドでコマンドやサブエージェントを動かしたままターンを終えた場合（「終わるまで待ちます」など）は、完了とは扱わず「実行中」のままにする。検証コマンドも走らない。バックグラウンドの作業が終わってエージェントが続きを報告したら、そのターンの終わりで完了になる。続きが始まらないまま作業がなくなった場合は、8秒後に完了とする。Codexにはこの仕組みがない。

**同時に動かす数：** 左下のスライダーのアイコンから設定を開く。上限（既定8件、最大20件）を超えた分は「順番待ち」になり、空きが出ると自動で始まる。Claude Codeは1件あたり約240MBを使うので、8件で約2GBが目安。

**環境変数：** 設定、または新しい作業の画面の鍵のアイコンから、プロジェクトごとに設定する。次に始める作業から反映される。値は暗号化して保存し、会話の記録や画面では `[env:変数名]` と表示する。コマンドを実行できるエージェントは値を読めるので、本番用の強い権限の値は入れないこと。

左の一覧のアイコン：ひし形に！＝あなたの判断待ち、回る円弧＝実行中または検証中、時計＝順番待ち、丸にチェック＝返答が完了、盾＝検証に成功、丸に×＝検証に失敗、縦2本線＝中断、三角に！＝異常。

| 操作 | キー |
|---|---|
| 依頼の間を移動 | `j` / `k` |
| 選択肢を選ぶ | 数字キー `1`〜`9` |
| 回答・追加指示を送信 | `Ctrl+Enter` |
| 作業の画面で、次の作業／前の作業へ | `Tab` ／ `Shift+Tab`（左の一覧の順。入力欄にフォーカスが移るのでそのまま書ける） |
| 要対応に戻る | `i` または `Esc` |
| 新しい作業 | `n` |

承認（許可／拒否）にはワンキーのショートカットを意図的に付けていない。ボタンを押す。

**表示の意味：**

| 表示 | 意味 |
|---|---|
| 人間待ち | 質問か承認を待って止まっている |
| 返答が完了 | エージェントの返答が終わった。**タスクが完了したという意味ではない** |
| 検証に成功 | 検証コマンドが終了コード0で終わった。人間が「完了にする」を押すまでは完了ではない |
| 検証に失敗 | 検証コマンドが失敗した。完了にはできない。作業の画面で出力を確認できる |
| 順番待ち | 同時に動かす数の上限のため、まだ始まっていない |
| 中断 | ターンが途中で止まった。会話から追加の指示を送ると再開する |
| 失効 | そのカードにはもう回答できない（ターンが終わった、プロセスが終了した、Control Roomが再起動した） |
| プロセスなし | メモリを使っていない。会話は保存されており、次のメッセージで再開する |

**メモリを空ける：** 返答が完了したClaude Codeの作業は「メモリを空ける」で約240MBを解放できる（実測）。Codexは1つのプロセスを全セッションで共有しているため、セッション単位の解放はない。

## 4. エージェントの設定

Control Roomは各社のCLIと同じ設定をそのまま使う。上書きも追加注入もしない。

- Claude Code：`CLAUDE.md`、`.claude/`、`~/.claude/settings.json`（許可ルール、既定モデル、フック、プラグイン）。モデルのトグルで「設定どおり」を選ぶと `~/.claude/settings.json` の `model` に従い、ほかを選ぶとその作業だけ上書きする。
- Codex：`AGENTS.md`、`~/.codex/config.toml`、`.codex/`。承認ポリシーは開始フォームで「設定ファイルに従う／毎回確認する」を選べる。
- すでに許可ルールで許可済みの操作は、Inboxに出ずに実行される（各ツールの仕様どおり）。

環境変数：エージェントはControl Roomを起動したコンソールの環境変数を引き継ぐ。ただしClaude Code向けには `CLAUDE*` と `ANTHROPIC*` で始まる変数を除外している（プランのログインを使うため。`ANTHROPIC_API_KEY` があるとAPI課金になる）。その上に、設定画面で登録したプロジェクトの環境変数が重ねられる（同じ名前なら登録した値が優先）。

## 5. データとログ

| 場所 | 内容 |
|---|---|
| `%LOCALAPPDATA%\AgentControlRoom\control-room.sqlite` | イベントログ（状態の元）、エージェントからの生データ、会話の記録 |
| `%LOCALAPPDATA%\AgentControlRoom\control-room.log` | 予期しないエラーの記録 |
| `~/.claude/projects/` | Claude Codeの会話（Claude Code自身が管理） |
| `~/.codex/` | Codexの会話（Codex自身が管理。Codexアプリの履歴にも現れる） |

SQLiteファイルには、コマンド文字列・会話本文・プロバイダーの生データが平文で入る。共有やコミットをしないこと。中身は任意のSQLiteビューアで読める。

```sql
SELECT seq, datetime(at/1000,'unixepoch','localtime') AS at, type, payload FROM events ORDER BY seq DESC LIMIT 50;
```

## 6. 障害時の動作と復旧

| 起きたこと | Control Roomの動作 | 対処 |
|---|---|---|
| Control Roomが落ちた／強制終了した | 起動していたエージェントのプロセスはOSが全て終了させる（Job Objectのkill-on-close、実機確認済み） | 再起動する |
| 2つ目を起動した | 既に開いているウィンドウを前面に出す（未検証）。コンソール版（`npm start`）が動いている場合は、ポートが使用中というエラーを出して終了する | 既に開いているウィンドウを使う |
| 再起動した | 履歴は復元される。再起動前に未回答だったカードは「失効」、実行中だったセッションは「中断」になる。「実行中」と誤表示はしない | 中断セッションの会話を開き、追加の指示を送る（再開される）。**未回答だった質問・承認は復元されない**ので、必要なら改めて指示する |
| Codexのプロセスが落ちた | そのプロセスに載っていた全Codexセッションが「異常」になり、未回答カードは失効 | 各セッションに追加の指示を送ると新しいプロセスで再開する |
| ウィンドウが見当たらない | 閉じてもトレイに残っている | 通知領域のアイコンをクリックする |
| 画面に「接続が切れました」 | 表示は最新ではない可能性がある旨を表示し、自動で再接続を試みる | Control Roomが動いているか確認する |
| 「このタブは認証されていません」 | トークンなしで開いた | 起動時のURLから開き直す |
| カードを押したが「送信されませんでした」 | 既に失効・回答済み、または選べない決定だった。エージェントには何も送られていない | 表示された理由を確認する |
| エージェントが残したプロセスがある | セッション行に「残存n個を終了」ボタンが出る。自動では終了しない | 不要なら押す。開発サーバーなど使い続けたいものは押さない |

## 8. 既知の制限（MVP v0.1）

- Decision Memory、優先度付け、日次ダイジェストは未実装。
- 完了の判定は検証コマンドの終了コードだけで行う。仕様レビューやコンフリクトの確認はしない。
- 環境変数に開発用／本番用の区別はない。順番待ちはControl Roomを再起動すると「中断」になる。空きメモリによる開始の保留は未検証。
- エージェントの発言は完了ごとに表示される（途中経過は流れない）。
- MCPサーバーからの入力要求は標準のフォーム形式のみ対応。URLを開かせる形式などは**自動的に辞退**して会話に記録する。

## 9. 公開リポジトリへの反映（管理者向け）

開発は非公開のリポジトリで行い、公開リポジトリ（GitHub の `orrery`）には、その時点の master の中身を **1 つのコミット**として反映する。公開側には開発の履歴を持ち込まない。

```powershell
npm run sync-public            # 公開用のリポジトリにコミットするだけ（push しない）
npm run sync-public -- --push  # コミットして GitHub に push する
```

- 公開用のリポジトリは、このフォルダの隣の `..\orrery`（環境変数 `ORRERY_PUBLIC_DIR` で変えられる）。
- 次のどれかに当たると、何も変えずに中止する。
  - このリポジトリが master でない、またはコミットしていない変更がある
  - 公開用のリポジトリが GitHub と一致していない
  - 公開用のリポジトリの最新コミットが、このスクリプト以外で作られている（GitHub で PR をマージした等）
  - 公開用のリポジトリのコミット作成者が GitHub の noreply アドレスでない
  - 公開するファイルに、このPCのホームフォルダのパス・ユーザー名・git のメールアドレスが含まれている
  - `npm test` が失敗する（`--skip-tests` で省略できる）
- 追加・変更された画像は一覧で表示する。画像の中は検索できないので、個人の情報が写っていないか目で確認する。
- コミットのあと、公開側の中身が master と完全に一致すること（ツリーのハッシュ）を確かめる。一致しなければ push しない。
- コミットには `Synced-From: <master のコミット>` を付ける。どの時点の master を反映したかがわかる。

**外部からの PR：** GitHub 上ではマージしない（次の反映で上書きされてしまう）。変更をこのリポジトリに取り込み（例：`gh pr diff <番号> -R Takana-12/orrery | git apply`）、ブランチで確認してマージし、反映する。そのあと PR に取り込んだ旨を書いて閉じる。
