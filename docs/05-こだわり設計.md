# こだわり（ユーザーの好み・方針）の設計メモ

別のAIが機能を再現できるように、目的、保存形式、責務、移行の決まりをまとめる。画面の見た目は `design.md` を参照。

## 1. 目的と成功条件

こだわりは、今回だけの仕様ではなく、今後の作業にも繰り返し使う本人の判断基準。UI・操作感、文章・言葉づかいなどの**セクションごとに一つのプロンプト**として保つ。セクション内を個別の項目、小見出し、プロジェクト別の編集欄に分けない。段落と改行は使える。

- セクション内に保存する `KnowledgeEntry` は最大一つ。新しい方針は既存の文章に統合する。
- 新しい作業の先頭に、関係するセクションを添付する。添付上限は**セクション本文ごとに5,000文字**。見出しは数えない。
- 全体6,000文字の共通上限は設けない。複数のセクションを選んでも、それぞれが上限まで添付される。
- 添付上限と保存は分ける。結合や追記で5,000文字を超えても保存した全文は切らない。画面とコピーには全文を出し、超過時は「添付は先頭5,000字まで。全文は保存されます。」と伝える。
- 送る文章は `### セクション名` の下に本文をそのまま置く。自動的な箇条書き化、改行の `/` への変換、繰り返し回数での並べ替えを行わない。

## 2. 入口と使うAI

| 入口 | 処理 | 更新の扱い |
|---|---|---|
| 指示から自動記録 `Knowledge.heard()` | 指示・追加指示・却下の理由から繰り返し使える方針を読む | `seen: false`。inboxに未読を出す |
| こだわり画面の編集 | 各セクションの一つの入力欄で全文を編集 | `seen: true` |
| AIと整える `KnowledgeTune` | 指示文や要望を実行せず、こだわりとして整理 | `seen: true`。変更をチャットに表示 |

設定 → こだわりで、自動記録とAIと整えるに別々のAI・モデル・思考量を選べる。保存先は `knowledge.captureAi` / `knowledge.tuneAi`。旧設定の既定はClaude Haiku / Sonnet。空のモデル・思考量は各プロバイダーの既定。受け付け時のAIを使い、失敗時に他のAIへ自動で切り替えない。

共通の `PreferenceReader` は以下を指示する。

- どの作業にも使える一般的な方針を記録し、作業場所だけを理由にプロジェクト限定にしない。
- セクション内を細分化せず、一つの指示文としてまとめる。
- 保存済みのセクションには原則 `update` で統合後の全文を返す。変更を指示されていない方針と、守り方に関係する理由を落とさない。
- 既存の本文はJSONで**全文**を渡す。160字・300字で省略すると、書き直すときに後半の条件が失われるため。
- 自動記録の順番待ちでは、実際に読み始める時点の最新の本文を渡す。
- 読み取り中に書き換え・移動・削除の対象が編集された場合は、古い応答による変更を反映しない。自動記録は作業の記録、AIと整えるはチャットで見送った理由を伝える。

## 3. 保存形式と旧データの移行

`KnowledgeDomain { id, name, description, always, order }` がセクション。`KnowledgeEntry { id, domainId, text, sessionId, scope, hits, createdAt, updatedAt, seen }` がその一つのプロンプト。旧イベントとAPIに互換性を持たせるため内部の `entry` という名前は残す。`text` が全文で、理由も必要ならこの中に書く。

起動時、`ControlCore.start()` が旧形式の複数項目をセクションごとに結合する。

1. 記録日時順に並べ、段落間を空行でつなぐ。完全に同じ本文は一つにする。
2. 旧イベントの `why` はreducerで `text（理由: why）` に畳み込む。`quote` は使わない。
3. プロジェクト限定の旧項目は、`プロジェクト「名前」（パス）に限り、次の方針を適用する。` を本文の前に付ける。限定条件を消さず、以後の `scope` は `all`。
4. 最初の項目のid・記録日時を維持し、hitsは合算、更新日時は最新、seenは全項目を見ていたときだけtrue。
5. **`knowledge.prompts_set { entries, remove }` の一イベント**で旧項目を置き換える。停止しても更新と削除の片方だけが残らない。
6. 元のイベントは消さない。再起動時は置換イベントまで再生され、再度結合しない。5,000文字を超えた全文も保持する。

追加・セクションの移動・削除して「その他」へ移す操作でも同じ結合関数を使う。移動先に本文があれば合わせて一つにし、上書きしない。手で全文を書き換える `update` は、そのセクションの本文を置き換える。

## 4. 層と責務

| 層・ファイル | 責務 |
|---|---|
| `core/src/knowledge.ts` | 純粋関数。上限 `KNOWLEDGE_LIMITS.sectionText`、文章の結合、旧scopeの条件化、添付文とセクションの選択 |
| `core/src/core.ts` | 起動時移行、一セクション一プロンプトの維持、イベントの発行 |
| `core/src/events.ts` / `reducer.ts` | 原子的な置換イベントと旧イベントの読み取り |
| `provider-shared/src/preferences.ts` | 共通の読み取り・整理プロンプト、JSON応答の検証 |
| `provider-claude` / `provider-codex` | 選んだAIへの問い合わせ。Codexは環境・MCP・プラグインを無効にした一時スレッド |
| `server/application/assistant.ts` | AIのポート、振り分け、読み取りの順番待ち |
| `server/application/knowledge.ts` | 自動記録、添付、AIによる変更の共通入口 `apply()`、手での編集 |
| `server/application/knowledge-tune.ts` | 専用チャット、順番待ち、会話の永続化 |
| `server/application/read-model.ts` | 本文、セクション、上限、チャットをsnapshotにする |
| `server/interface/http/routes.ts` | 既存 `/api/knowledge/entries` 等のAPI。追加も同じセクションへの統合になる |
| `public/js/logic/knowledge.js` | DOM・通信を持たない表示モデル、添付量、全文コピー、楽観的な結合・移動・削除 |
| `public/js/logic/actions.js` | API操作と楽観的更新。拒否時にロールバックして通知 |
| `public/js/ui/views/knowledge.js` | 一セクション一入力欄、保存・削除・コピー、添付量の表示 |

AIによる変更は `Knowledge.apply(edit, ctx)` に集める。新領域 → remove → update → add → reinforce の順。領域は既存idまたは `newDomains` のkeyを使う。追加先に本文があれば統合し、変更一覧では `update` として扱う。同文によるreinforceは同じセクション内だけで判定する。領域は最大30、上限を超えた新領域は「その他」を使う。文字列はsecretの伏せ字処理を通す。

小さい記録はすべて添付する。合計が1,500字を超える場合は関連セクションを最大3つ選び、「常に付ける」を追加する。選択が8秒で返らなければ「常に付ける」だけで進める。5,000字を超えたセクションは、作業の記録にも上限まで添付したことを残す。

## 5. 編集とチャット

- 各セクションに一つだけ入力欄を置く。空のセクションも同じ欄から作れる。個別項目の追加欄、移動メニュー、プロジェクト選択、件数上限を置かない。
- 変更したときだけ右端に保存ボタンを出す。Ctrl+Enterでも保存、Escで編集前に戻す。フォーカスを外しただけでは保存しない。空欄への変更は削除にせず、削除ボタンを使う。
- セクションのコピーは `### セクション名` と保存した全文。添付上限で切った文章をコピーしない。押すと一時的に✓になり、失敗時は通知する。
- 名前、選択に使う説明、「常に付ける」、セクションの追加・削除は従来どおり使える。
- 長文入力欄の自動伸縮は共通の `ui/dom.js` に任せる。幅の監視中に高さを書き換えるとResizeObserverの配信ループになるため、監視結果をまとめて次の描画フレームで調整する。
- AIと整えるは `#/knowledge/tune`。人間の発言と処理中をすぐ表示し、裏で読んだ変更を反映する。失敗時は変更しない。会話は固定id `knowledge-tune` でSQLiteに保存、表示は直近80件、AIには直近8件を渡す。

## 6. 確認すること

- `core/test/knowledge.test.ts`: 旧項目の結合・理由・scope・未読の移行、再起動で再結合しないこと、全文保持、移動先との結合、各5,000字・共通上限なし、改行の保持。
- `provider-shared/test/preferences.test.ts`: 両AIが全文を受け取り、一プロンプトの方針を使い、自動記録の全文更新を検証すること。
- `server/test/knowledge.test.ts`: 自動記録・専用チャット・セクション選択・最初のメッセージへの添付。
- `server/test/ui-logic.test.mjs`: 添付量と全文コピー、統合・移動の即時反映、失敗時のロールバック。
- `server/test/ui-harness.mjs`: 通常・上限付近・超過のセクションと専用チャットを含む全画面のDOM。ライト／ダーク、狭い画面でも確認する。
- `npm run test:knowledge-ui`: 分離したElectronプロファイルとテスト用SQLiteで、旧項目の移行 → 実際の画面で編集・保存 → HTTP → SQLite → 再読込・再起動を確認する。AIプロバイダーへの問い合わせは無効化し、結果とライト・ダーク・幅520pxの画像を `.control-room/knowledge-ui-*/` に保存する。

`npm test` と `npm run typecheck` を実行する。本物のAIを使う読み取りは `tune-live.ts` で確認できるが、プランの利用枠を使うため通常の回帰テストには含めない。
