# 複数ワークスペースと「使うAI」の設計メモ

別のAIがこの機能を作り直せるように、決めたことと理由を残す。

## 1. 複数ワークスペース

### 振る舞い
- 新しい作業の入力欄の左下にあるワークスペースのチップは「いくつでも選べる」チェックリストになっている。別のものを押すと、それも追加でチェックされる。もう一度押すとチェックが外れる。押すとすぐ変わり、メニューは開いたままなので続けて選べる。
- 最初にチェックしたものが**メイン**になる。エージェントはメインのフォルダ（または worktree）から作業を始め、承認・worktree・前回使ったAIはメインの設定に従う。メインのチェックを外すと、次にチェックしたものがメインになる。
- チップにはメインの名前と「+N」を表示する。全部の名前はツールチップと、入力欄のプレースホルダー（「A・Bで何をしますか？」）に出す。
- 「別のフォルダを開く」で選んだフォルダも追加でチェックされる。まだ登録されていないフォルダは `path:<folder>` としてチェックされ、送信時に登録される。
- 音声入力の確認画面でも、作業ごとのワークスペースのチップが同じように動く。
- 作業の一覧・詳細・レールには「メイン・ほか」の名前を併記する（`selectors.workspacesOf`）。

### データ
- `AgentSession.extraProjectIds?: string[]`。メイン以外のワークスペースを、チェックした順に持つ。`session.created` イベントに入れて保存するので、再起動後も残る。項目がないとき（以前の作業）はメインだけ。
- read-model は `extraProjectNames` を加えて画面に渡す。

### エージェントへの渡し方
- `StartSessionRequest.extraDirs`：ほかのワークスペースのフォルダ。
  - Claude：`additionalDirectories` に追加する（添付ファイル用の `readDirs` と並べる）。
  - Codex：`config.sandbox_workspace_write.writable_roots` に追加する（`codex --add-dir` と同じ設定）。
- 最初のメッセージの前置き（デフォルトメッセージ・こだわりと同じ場所）に、ほかのワークスペースの名前と場所を1行ずつ入れる（`sessions.alsoNote`）。会話の記録には人が書いた文だけを表示する。
- 再開（プロセスが止まった後の `send`）でも同じ `extraDirs` を渡す。
- ほかのワークスペースには worktree を作らない。フォルダをそのまま使う。環境変数はメインのものだけを渡す。

### 層
- 状態を持つのは `ui/views/new-work.js`（チェックしたもの）。選択中のものは `store.newDraft.workspaces` に入れて、画面を移っても残す。最後に送ったものは `localStorage` の `crProjects`（メインは `crProject`。音声入力のヒントとして使う）。
- チップの部品は `ui/menu.js` の `multiPicker`。
- 送るのは `logic/actions.startWork({ workspaces: [...] })`。未登録のフォルダを先に登録してから `POST /api/sessions { projectId, extraProjectIds }` を送る。

## 2. 使うAI（サブスクリプション）

### 振る舞い
- 設定 →「使うAI」に、エージェントごとのスイッチを置く（アイコン + 名前）。最後の1つはオフにできない。
- オフにしたものは、どのAI選択（新しい作業・サイドチャット・音声・こだわり）にも出さない。残量（レールの電池・利用状況画面）とログインの案内も出さない。新しい作業で選んでいたAIがオフになったら、使っているものへその場で切り替える。
- サーバーは、オフのエージェントのログイン状態や残量を確認しに行かない（使っていないものを起動しない＝軽さ）。音声の振り分けでも、オンのものだけを候補にする。

### データ
- `Settings.providers?: ProviderId[]`。項目がない（以前の設定）ときは全部オンとして扱う。値は必ず `enabledProviders(settings)` を通して読む。read-model は値を埋めてから画面に渡す。
- 検証（`core.setSettings`）：知っているエージェントだけを、決まった順で残す。空にはしない。画面側の楽観的更新（`optimistic.settingsEffect`）も同じ規則にする。

### 拡張（例：Gemini を足すとき）
1. `core/types.ts` の `ProviderId` と `PROVIDER_IDS` に追加する。
2. `packages/provider-gemini` にアダプタ（`ProviderAdapter`）を作り、`app.ts` の adapters に登録する。`Accounts.auth` に初期値を足す。
3. 画面側は `logic/agents.js` の `AGENTS`、`ui/vocabulary.js` の `PROVIDER`、`ui/icons.js` のアイコンに追加する。
4. 設定のスイッチ・AI選択・残量表示は `AGENTS` / `usableAgents()` から作られるので、それ以上の変更はいらない。

## 3. 確認すること

- `packages/server/test/ui-logic.test.mjs`：未登録フォルダを含む `startWork`、オフにしたらすぐ消えること、拒否されたら元に戻ること。
