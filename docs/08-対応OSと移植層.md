# 対応 OS と移植層（Windows / macOS）

Orrery を Windows と macOS の両方で動かし、**片方を直してももう片方が壊れない**ようにするための設計メモです。別の人（や AI）が同じ構造を再現・拡張できるように、決めたことと理由を書きます。v0.6.0 で導入しました。

## 1. 方針

1. **OS に依存するコードを置いてよい場所は 2 か所だけ。** それ以外のコードは「いまどの OS か」を一切たずねない。
2. その 2 か所は、**OS ごとの実装を 1 つの形（インターフェース）の裏に隠す。** 呼ぶ側は形だけを知っている。
3. 1 と 2 が守られているかは、人の注意ではなく**テストが機械的に確かめる。**
4. 自分の手元にない OS は、**CI が両方の OS で同じテストとアプリの起動確認を行う**ことで確かめる。

リポジトリは 1 つ、ブランチも 1 つです。OS 別のブランチやフォルダの複製は作りません（複製すると、機能を足すたびに 2 回書くことになり、いずれ片方が古くなります）。

## 2. 2 つの置き場所

| 場所 | 何を隠すか | 形の定義 | Windows の実装 | macOS の実装 |
|---|---|---|---|---|
| `packages/host/`（`#host`） | サーバー側が OS に頼むこと：プロセスの所有、秘密の暗号化、空きメモリ、プログラムの検索、既定のデータフォルダ、ブラウザを開く、フォルダ選択 | `src/types.ts` の `Host` | `src/windows/` | `src/mac/` |
| `apps/desktop/platform/` | デスクトップアプリの殻（Electron）で違うこと：ビルドしたアプリの置き場所と形、トレイ、メニュー、ログイン時の起動、更新後の再起動、マイクの許可 | `windows.mjs` と `mac.mjs` が同じ名前を export する | `windows.mjs` | `mac.mjs` |

どちらも、**使う実装を選ぶのは `index` の 1 行だけ**です（`packages/host/src/index.ts`、`apps/desktop/platform/index.mjs`）。選ばれなかった OS のファイルは読み込まれません（Windows の実装は `kernel32.dll` を開くので、Mac で読み込むとそれだけで失敗します）。

層の中での位置は変わりません。`#host` は `#provider-*` と同じ「外の世界」で、`application/` や `infrastructure/` から内向きに呼ばれます（`packages/server/src/app.ts` の冒頭の図）。

画面（`packages/server/public/js/`）で OS によって変わる文言とキー（⌘ / Ctrl、「メニューバー」/「通知領域」、暗号化の説明）は `logic/platform.js` の 1 ファイルに集めています。UI のモジュールはそこから取るだけです。

## 3. 同じ機能を、それぞれの OS でどう実現しているか

| 機能 | Windows | macOS | 違いと理由 |
|---|---|---|---|
| 起動したエージェントと、その子孫プロセスをまとめて所有する（数える・メモリを測る・一括で終了する） | Job Object（`windows/winjob.ts`） | プロセスグループ＋親子関係の追跡（`mac/job.ts`） | macOS には Job Object がない。ルートのプロセスを**グループのリーダーとして起動**し（`host.ownedSpawn`）、「グループが同じ」または「親が所有済み」のプロセスを 5 秒ごとの計測のたびに取り込む。pid は使い回されるので、**開始時刻と組で**覚える |
| Orrery が落ちたとき、起動したものを残さない | OS が保証（kill-on-close） | 通常の終了・未処理の例外では Orrery 自身が終了させる（`process.on('exit')`） | **macOS では `kill -9` や電源断のときだけ保証がない。** エージェント本体はパイプが切れて自分で終わるが、エージェントが起動したもの（開発サーバーなど）は残りうる。Windows にはこの穴はない |
| 環境変数の値を暗号化して保存 | DPAPI（`windows/dpapi.ts`） | ランダムな 256 ビットの鍵をログインキーチェーンに置き、値は AES-256-GCM で封をする（`mac/keychain.ts`、`sealed.ts`） | どちらも「同じ PC の同じユーザーだけが開ける」。鍵の読み書きは `/usr/bin/security` 経由。キーチェーンの項目は「作ったプログラム」を信頼するので、**更新のたびに作り直される Orrery 自身を登録すると毎回確認が出る**ため |
| 空きメモリ（順番待ちの判定） | `os.freemem()` | `vm_stat` の free＋inactive＋speculative | macOS の `os.freemem()` は「誰も触っていないページ」だけを数え、メモリが余っていてもほぼ 0 になる。そのまま使うと順番待ちが永久に進まない |
| git・gh・npm・codex を見つける | PATH（`where.exe`） | **ログインシェルの PATH を取り込む**（`adoptShellPath`）＋よくある場所 | Finder から起動したアプリの PATH は `/usr/bin:/bin` 程度で、Homebrew や nvm が入っていない |
| データの場所 | `%LOCALAPPDATA%\AgentControlRoom` | `~/Library/Application Support/AgentControlRoom` | フォルダ名は同じにした（文書と報告で迷わないため） |
| ビルドしたアプリ | `release\Orrery-win32-x64\Orrery.exe` | `release/Orrery-darwin-<arch>/Orrery.app` | macOS は `NSMicrophoneUsageDescription` を入れ、ビルド後に ad-hoc 署名をやり直す |
| アプリの登録 | スタートメニューのショートカット（`install-shortcuts.ps1`） | `~/Applications/Orrery.app` へのリンク（`install-app.sh`） | どちらも**コピーしない**（更新で入れ替わるのは `release/` の中身だから） |
| 更新後の入れ替えと再起動 | `update-swap.ps1` | `update-swap.sh` | 同じ手順（終了を待つ→残りを終わらせる→入れ替える→失敗したら戻す→起動） |
| 常駐 | 通知領域のアイコン | メニューバーのアイコン＋Dock（件数のバッジ） | macOS は専用のメニュー（編集メニューがないと ⌘C / ⌘V が効かない）と、Dock のクリックでウィンドウを戻す処理が要る |
| 終了 | トレイの「終了」 | メニューバーの「終了」、⌘Q、Dock の「終了」 | macOS の ⌘Q は人の操作なので、動いている作業があれば確認する |

## 4. 機能を足す・直すときの手順

**OS に関係ない変更（ほとんどの変更）**：いままでどおり書くだけです。`#host` と `platform` を通している限り、両方の OS で動きます。push すると CI が両方で確かめます。

**OS に頼ることが新しく必要になったとき**：

1. 形に 1 つ足す：`packages/host/src/types.ts` の `Host`（殻の話なら `apps/desktop/platform/` の両ファイルに同じ名前）。「何をしてほしいか」を OS の言葉を使わずに書く。
2. `windows/` と `mac/` の**両方**に実装を書く。片方でやることがなければ、何もしない実装を書いてコメントで理由を残す（例：`adoptShellPath` は Windows では空）。
3. `packages/host/test/host.contract.test.ts` に、どちらの OS でも成り立つべき期待を 1 つ足す。OS の道具の出力を読む場合は、読む部分を純粋な関数に切り出して `mac-parsers.test.ts` のように全 OS で試す。
4. push して、CI の Windows と macOS の両方が緑になるのを見る。

**やってはいけないこと**：`process.platform` を見る `if` を、上の 2 か所以外に書くこと。`platform-guard.test.ts` が、行番号つきで落とします。

**別の OS（Linux など）に対応するとき**：`packages/host/src/<os>/index.ts` と `apps/desktop/platform/<os>.mjs` を足し、それぞれの `index` で選ぶ。`mac/job.ts` と `mac/ps.ts` は POSIX 一般で動くように書いてあるので流用できる。足りないのは秘密の保管（キーチェーンに当たるもの）と、殻の細部。

## 5. 正しさをどう確かめているか

主観（「たぶん動く」）ではなく、次の機械的な検査を基準にします。すべて `npm test` と CI（`.github/workflows/ci.yml`、Windows と macOS）で走ります。

| 検査 | 何を保証するか | ファイル |
|---|---|---|
| ホストの契約テスト | プロセスの所有（孫まで入る・親が先に終わっても残る・一括で終わる）、秘密の往復と改ざんの拒否、プログラムの検索、空きメモリが、**その OS の実装で**成り立つ | `packages/host/test/host.contract.test.ts` |
| パーサーのテスト | `ps`・`vm_stat`・`lsof` の出力の読み取りと、封をした値の開閉（全 OS で実行） | `packages/host/test/mac-parsers.test.ts` |
| ガード | 2 か所以外に OS 依存のコードがない／実装を選ぶのは `index` だけ | `packages/host/test/platform-guard.test.ts` |
| 殻の形のテスト | `windows.mjs` と `mac.mjs` が同じものを export し、殻が呼ぶ名前がすべて両方にある／参照するファイルが実在する | `apps/desktop/platform.test.mjs` |
| 更新の契約 | 既に入っている Windows 版（v0.5 以前）が更新時に実行するパスと引数が残っている（6 章） | 同上 |
| 入れ替えスクリプト | `update-swap.sh` が、待つ→入れ替える→起動する→片付ける、を行う（macOS の CI で実行） | 同上 |
| スモークテスト | **ビルドしたアプリそのもの**が、起動し、UI と API に答え、自分のビルド元を知っていて、頼まれたら完全に止まる（両 OS の CI で実行） | `scripts/smoke-packaged.mjs` |
| 画面が変わっていないこと | Windows の全画面の DOM が変更前と一致（リファクタリングのとき手で実行） | `packages/server/test/ui-harness.mjs` |

**CI で確かめられないこと（macOS）**：メニューバーのアイコンの見え方、通知、マイクの許可ダイアログ、ログイン時の起動、Finder から開いたときの PATH、実際のエージェント（Claude Code / Codex はログインが要る）とのやりとり。これらは実機でしか見られません。実機で確かめたら、Runbook の「既知の制限」から外してください。

## 6. 既に入っているアプリとの約束（動かしてはいけないもの）

アプリの更新は「**古いアプリ**が、**新しいソース**の中のスクリプトを実行する」形で行われます。何を実行するかを決めるのは古いアプリのコードなので、次を動かしたり名前を変えたりすると、そのアプリは入れ替えの途中で止まり、**終了したまま二度と起動しません。**

- `apps/desktop/package.mjs`（引数 `--out <dir>`）
- `apps/desktop/update-swap.ps1`（引数 `-WaitPid -Exe -Log -Arguments -WorkingDirectory -Release`）と、そこから呼ばれる `apps/desktop/install-shortcuts.ps1`
- Windows のビルド先の名前 `Orrery-win32-x64` と、その中の `Orrery.exe`
- v0.6.0 以降の macOS 版に対しては、同じ理由で `apps/desktop/update-swap.sh`（引数 `--wait-pid --exe --log --cwd --release --name`）、`apps/desktop/install-app.sh`、`Orrery-darwin-<arch>/Orrery.app`

OS 別のスクリプトを `platform/` の下にまとめたくなりますが、この約束があるので `apps/desktop/` の直下に置いたままにしています。

## 7. macOS で決めたことの補足

- **署名と公証はしていません。** 利用者が自分の Mac でビルドするので、ダウンロードしたアプリに付く隔離の印が付かず、Gatekeeper の対象になりません。配布用のバイナリ（.dmg）を作る場合は、Apple Developer ID での署名と公証が別途必要です。
- ad-hoc 署名はビルドごとに変わるため、**更新のあとでマイクの許可をもう一度たずねられることがあります。**
- Apple シリコン（arm64）を CI で確かめています。Intel Mac でも同じコードでビルドできるはずですが（`Orrery-darwin-x64`）、確かめていません。
- 「ログイン時に開始」は Electron の `setLoginItemSettings` を使います。署名のないアプリで macOS が受け付けるかは実機で未確認です。
