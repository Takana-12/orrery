# スケジュール（決まった時刻に始まる作業）の設計メモ

別のAIがこの機能を作り直せるように、決めたことと理由を残す。

## 1. 振る舞い

- レール下端の時計アイコン（`#/schedules`）で開く。1 スケジュール = 1 行：名前（空なら指示文の頭）、いつ（「平日 09:00」「2時間ごと」「12/01 12:00 に1回」）、ワークスペース、AI、送り先の種類。右側に「前回の実行（1アイコン + 1語、押すとその作業を開く）」「次回」「今すぐ実行 ▷」「オン/オフのスイッチ」。前に進める操作は右端。
- 行を押すとその下にフォームが開く（カードにせず、行の続きとして置く）。もう一度押すか Esc で閉じる。閉じると書きかけは捨てる（「元に戻す」は置かない）。一覧の下・右端の ＋ で新しいフォームが一覧の下に開く。
- フォーム：名前／指示文（プレースホルダー「何を作りますか?」）／ワークスペースと AI のチップ（新しい作業と同じ `picker` と `aiPicker`）／いつ（時刻・間隔・1回のセグメント）／送り先（Webhook URL）とテスト送信／このスケジュールだけの環境変数／済んだら片付ける。保存は右下（Ctrl+Enter・Ctrl+S でも）。削除は左下。
- **押した瞬間に変わる**：保存・オンオフ・今すぐ実行・削除はすべて `logic/schedules.js` の効果で即座に一覧に出る（次回の時刻も画面側で計算）。断られたら戻し、保存ならフォームを書いた内容と理由つきで開き直し、通知も出す。テスト送信だけは相手の返事そのものが結果なので、ボタンが押した瞬間に回り、届いた／送れなかった理由をボタンの横に出す。

## 2. いつ実行するか

- 規則は 3 種類（`core/src/schedule.ts`）：`daily`（HH:MM と曜日。全曜日＝毎日）、`interval`（5分〜7日、前回の実行から数える）、`once`（日時。実行後は自分でオフ）。時刻はこのPCのローカル時刻。
- `nextRunAt(rule, after)` が「after より後の最初の時刻」を返す純粋関数。画面にも同じものの JS 版（`public/js/logic/schedule-rule.js`）があり、`test/schedule-rule.test.mjs` が同じ答えを出すことを確かめる。**片方を変えたら両方変える。**
- サーバーは 5 秒ごとの見回り（`app.ts` の sampler）で `Schedules.tick()` を呼ぶ。`nextAt` を過ぎていたら、**先に次の時刻を決めて保存してから**始める（同じ時刻で 2 回始まらない）。
- アプリが止まっていた間に来た時刻は、次に起動したとき **1 回だけ** 実行する（逃した回数分は実行しない）。
- 同じスケジュールの前回の実行がまだ動いている（順番待ち・実行中・判断待ち）ときは始めず「見送り」と記録する。短い間隔で作業が積み上がらないため。「今すぐ実行」は人の明示的な操作なので見送らない。
- 次回の再計算は、規則が変わったときとオンにし直したときだけ。名前や指示文の変更では次回は動かない。

## 3. 実行されるもの

- 1 回の実行は**ふつうの作業**：`Sessions.start()` を通る（実行枠の順番待ち、worktree、デフォルトメッセージ、こだわりも同じ）。ホームとinboxにそのまま出るので、質問や承認が来ても人の番として見える。
- 承認の任せ方はワークスペースの設定に従う（音声入力と同じ。Codex に無い `edits` は `ask`）。worktree もワークスペースの設定に従う。
- 作業には `AgentSession.scheduleId` が残る（`session.created` イベント）。HTTP の `/api/sessions` からは受け取らない（`App.startSession` で捨てる）。作業の記録の先頭に「スケジュール「…」の予定どおりに始めた作業です」と書く。

## 4. 結果の送り先（Webhook）

- 返答が終わったら（`turn_finished`、後から送る指示が無いとき）最後の返答 `lastText` を 1 回送る。失敗（`error` / `interrupted` / `unknown`、ただし利用制限で自動再開を待っている間は除く）なら「失敗: …」を送る。始められなかったときも送る。見送りは送らない。
- 形は URL で決める（`infrastructure/webhook.ts`）：
  - Discord（`discord.com/api/webhooks/…`）：`content`。2000 字制限があるので 1900 字ごとに最大 5 通に分ける。`allowed_mentions: { parse: [] }` で、返答中の `@everyone` などで誰も呼ばれないようにする。429 は 1 回だけ待って送り直す。
  - Slack（`hooks.slack.com`）：`text`（3900 字まで）。
  - それ以外：`{ text, title, workspace, ok, sessionId, at }` の JSON。
- https のみ（http はこのPCの localhost だけ）。リダイレクトは追わない。10 秒で諦める。エラー文に URL を入れない。
- 送った・送れなかったは実行の記録（`runs[].delivery`）と作業の会話記録に残し、行のアイコンで見せる（送信済み／送れませんでした）。

## 5. 秘密の扱い

- Webhook の URL（中にトークンがある）と、スケジュールの環境変数は**秘密**。プロジェクトの環境変数と同じ `project_env` テーブルに、スコープ `schedule-hook:<id>`（名前 `WEBHOOK_URL`）と `schedule:<id>` で暗号化して置く（`#host` の protect：Windows は DPAPI、macOS はキーチェーンの鍵）。スケジュール本体（`schedules` テーブルの JSON）には入れない。
- 画面に送るのは「Discord・discord.com」のような種類とホスト、変数名と長さだけ。保存した URL は二度と表示しない（× で外す、鉛筆で別の URL に置き換える）。
- `Secrets.redact` は全スコープの値を見るので、URL や値がログ・会話記録・画面に出ても `[env:WEBHOOK_URL]` などに置き換わる。
- 作業の環境変数は「ワークスペースのもの → スケジュールのもの（同じ名前なら上書き）」（`Secrets.envForWork`）。再開・検証コマンド・人が押したコマンドでも同じ。
- スケジュールを削除すると、両方のスコープも消す。これまでに始まった作業は残る。

## 6. 済んだら片付ける

- スケジュールごとのスイッチ（既定オン）。毎日の実行がホームに積もり続けないため。
- 片付けるのは、返答が終わり、`Reader` が読み終え（`task.readTurn === lifecycleSince`）、質問・人の作業・失敗した検証・後から送る指示が無く、送り先があれば**送れた**ときだけ。どれかが残っていれば片付けず、ホームとinboxに残す（人の番は隠さない）。
- 片付け＝`setAccepted(true)`（完了にしてアーカイブ）。アーカイブからいつでも戻せる。

## 7. 層と置き場所

| 層 | ファイル | 役割 |
|---|---|---|
| コア | `core/src/schedule.ts` | 規則の検証 `settleRule` と次回 `nextRunAt`（純粋） |
| コア | `types.ts` / `events.ts` / `reducer.ts` | `AgentSession.scheduleId` |
| ユースケース | `application/schedules.ts` | 保存の検証、見回り（tick）、実行、送信、片付け、画面向けの view |
| ユースケース | `application/secrets.ts` | スコープつきの秘密（`scoped` / `setScoped` / `dropScope` / `envForWork`） |
| インフラ | `infrastructure/webhook.ts` | サービスごとの形、URL の検査、POST |
| インフラ | `infrastructure/sqlite-store.ts` | `schedules` テーブル |
| HTTP | `interface/http/routes.ts` | `POST /api/schedules`（作成・変更。`hook` / `env` も同じリクエスト）・`/api/schedules/test-hook`・`/:id/run`・`/:id/remove` |
| 画面ロジック | `public/js/logic/schedules.js` / `schedule-rule.js` | 楽観的な効果、言葉（規則・実行の状態）、フォームの下書き |
| 画面 | `public/js/ui/views/schedules.js` | 一覧とフォーム（`fetch` は呼ばない） |

- 新しいスケジュールの id は画面が作る（`crypto.randomUUID()`）。押した瞬間に出た行と、サーバーが保存したものが同じ id になるので、置き換えでちらつかない。
- 保存のリクエストは、全部を検証してから何かを書く（秘密も含めて）。断られたときに半分だけ変わることはない。
